# PearTree.pro — First Vertical Strategy

## Decision status
**Hypothesis to validate before 1.0.**

## Recommended wedge
Start with a **local-services / professional-services directory and lead-generation portal**.

Example structures:
- service category;
- city/region;
- provider profile;
- service listing;
- quote/contact lead;
- premium/promoted provider placement.

Do not lock the platform to a single industry. This is the first reference vertical used to validate PearTree.

## Why this vertical fits the architecture

### Strong SEO surface
It naturally creates user-intent pages:
- service;
- service + city;
- provider;
- category;
- comparison/guide;
- local informational content.

### Clear business value
A provider can understand the value of:
- visibility;
- inquiries;
- promoted placement;
- subscription;
- pay-per-lead.

### Reusable data model
Category, location, listing/provider and lead models generalize to many future verticals.

### Lower operational complexity
The first vertical can validate discovery and lead generation without requiring the full complexity of escrow, marketplace payouts, logistics or advanced booking.

## Candidate sub-verticals for validation

Good initial candidates have:
- meaningful customer value per lead;
- fragmented provider market;
- local search behavior;
- providers willing to pay for acquisition;
- sufficiently structured service data;
- manageable regulatory risk.

Examples include home services, local B2B services, events/services, property-related services and specialist professional directories. The final sub-vertical must be chosen using keyword demand, advertiser economics and direct customer interviews.

## Validation plan

Before hard-coding a vertical:
- 20–30 keyword clusters researched;
- top SERP competitors mapped;
- 10+ operator/provider interviews;
- willingness-to-pay tested;
- 3–10 design partners;
- one pilot project launched;
- lead conversion and provider response measured.

## Success signals
- first useful project can launch from configuration;
- directory pages acquire impressions organically;
- visitors submit qualified leads;
- providers respond to leads;
- at least some providers pay for visibility/leads/subscription;
- second project can be launched without a code fork.
